| --- | --- | --- | --- | --- |
| 1~5 | 아스팔트 | 5 | 0.4×3, 0.3, 0.5 | `..._아스팔트_건조.csv` |
| 6~10 | 자전거도로 | 5 | 〃 | `..._자전거도로_건조.csv` |
| 11~15 | 보도블럭 | 5 | 〃 | `..._보도블럭_건조.csv` |
| 16~20 | 콘크리트 | 5 | 〃 | `..._콘크리트_건조.csv` |

**세션 절차(반복)**: 앱 COLLECT → START → 직선 10~20초 → STOP → 파일탭 RENAME(노면·상태) → **매 5세션마다** `check_data.py data/` — FAIL이면 그 자리에서 재수집.
- ⚠️ 정속 확인: STATUS 속도가 목표 ±0.05 안에서 유지되는 구간만 유효
- ⚠️ 같은 노면도 위치를 바꿔 여러 세션(세션=파일 단위로 train/test가 갈리므로 다양성이 곧 일반화)

**수집 후**: `scp -r kick-ip:~/embedded_kickboard/RPi/data ./data_c1` → PC 보관(+클라우드 백업 권장)

## 4단계 — C2·C3 학습 (PC, 1~2시간)

```bash
python scripts/train.py data_c1/ --out models/road_rf.json          # 시간 윈도우(기본)
python scripts/train.py data_c1/ --window distance --window-pulses 8 --out models/road_rf_dist.json   # C3 비교
```

> **`--window-pulses` 환산** (PPR=2 실측 확정 · `WHEEL_CIRCUMFERENCE_M = 0.204`):
> **1펄스 ≈ 0.102 m**, 1회전 = 2펄스 ≈ 0.204 m.
> → `4`≈0.41 m · **`8`≈0.82 m(기본값·권장)** · `12`≈1.2 m · `20`≈2.0 m.
> 설계명세서 §7의 "거리 윈도우 1~2 m"에 맞추려면 `12`~`20`도 함께 돌려 비교한다.
> (시간 윈도우 기본 0.5 s @0.4 m/s ≈ 0.2 m 이므로, 거리 윈도우가 더 길다는 점을 감안해 해석할 것)
- 합격: 세션 CV 정확도 **≥70%** + 혼동행렬에서 위험(비포장)↔안전 혼동이 낮을 것
- 낮으면: 데이터 추가(특히 혼동 쌍) → 재학습. `--trees`, `--window-samples` 탐색
- 시간 vs 거리 결과 수치·혼동행렬 캡처 → **보고서 🟨 채움**
