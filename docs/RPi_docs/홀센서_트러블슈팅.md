# 홀센서(엔코더) 실기 트러블슈팅 기록 — 2026-08-24~25

> R1~R2 실기 세션에서 홀센서 무반응 문제를 추적한 전 과정과 결론. **배선·코드 변경의 근거 문서.**
> 결론만 보려면 [§5 최종 확정 배선](#5-최종-확정-배선)과 [§6 남은 작업](#6-남은-작업)으로.

## 1. 증상

- 바퀴를 돌려도, 자석을 대도 엔코더 펄스 0 — GPIO 입력이 한 레벨에 고정(처음 HIGH, 재배선 후 LOW)
- 모듈을 3번 교체해도(LM393 4핀 DM2246 → KY-003) 동일 증상

## 2. 진단 과정 (Pi 원격 측정)

| 단계 | 측정 | 결과 → 해석 |
| --- | --- | --- |
| 1 | GPIO17 레벨 감시(30s × 여러 번) | 자석·회전 무관 고정 → 신호가 핀에 안 옴 |
| 2 | 내부 풀업/풀다운/무풀 3종 읽기 | 전부 0 → 외부에서 GND로 끌림 |
| 3 | DO 선 분리 후 재측정 | **여전히 0** → 센서·배선이 아니라 핀 자체 의심 |
| 4 | GPIO17 출력 HIGH 구동 → 읽기 | **1 성공** → GND 직결 단락은 아님(약한 누설) |
| 5 | `pinctrl get 17` (빈 핀 + 풀업) | `ip pu \| lo` → **핀 손상 확정** (풀업으로도 안 올라감) |
| 6 | GPIO22로 이동 후 동일 테스트 | 유휴 HIGH ✅ · 자석 감지 LOW↔HIGH 전환 ✅ |

## 3. 원인 (확정 2건)

### 3-1. ⚠️ **Pi GPIO17(물리 11) 핀 손상 — 영구 사용 금지**
- 빈 핀에 내부 풀업을 걸어도 LOW. 내부에 GND로 새는 경로 발생(약 수 kΩ 누설로 추정).
- 유력 경위: 최초 장착 모듈이 **5V 풀업 내장형**(4핀 LM393 보드, DM2246) — DO의 HIGH가 5V로 출력되어 3.3V 전용 GPIO에 인가됨. **배선표 39행이 금지한 바로 그 구성.**
- 출력 구동은 되지만 입력으로는 불능. → `ENCODER_PIN`을 **GPIO22(물리 15)** 로 이동(config.py, 2026-08-24).

### 3-2. 현재 모듈(KY-003, makepcb S390)은 **래치형**
- 실측: 한 극을 대면 ON 유지, **반대 극을 대야 OFF** (LED로도 확인). 진짜 A3144(스위치형)가 아니라 래치 칩(US1881류) 탑재 보드.
- 결과: 같은 극 4개 자석으로는 첫 자석에서 ON으로 잠긴 뒤 펄스가 안 나옴.
- 해법: **자석 4개를 N-S-N-S 극성 교대 배치** → 자석마다 토글 → 회전당 엣지 4개.
- 코드는 **상승 엣지만** 카운트(`backend.add_edge_callback`) → **회전당 2펄스** 예상. `ENCODER_PULSES_PER_REV`는 `calibrate_encoder.py` 실측으로 확정(예상값 2).

## 4. 검증된 것 (이 세션에서 실측 통과)

- Pi 접속·새 레포 remote·`cw` 최신 코드 · Pi에서 **171 passed, 3 skipped**(skip=sklearn 학습 전용)
- `setup_check.py` 전 항목 PASS(RFCOMM 소켓 검사 포함) · `throttled=0x0`
- MPU-6050 FIFO 실측 **199.3Hz** (3초 598샘플)
- GPIO22 + KY-003(3.3V): 유휴 HIGH · 자석 감지/해제 전환 정상 · 바운스 없음

## 5. 최종 확정 배선

| KY-003 핀(인쇄) | Pi 연결 | 비고 |
| --- | --- | --- |
| `S` (신호) | **물리 15 (GPIO22)** 직결 | 외부 풀업 **불필요**(모듈 내장) · ~~물리 11(GPIO17)~~ 손상 금지 |
| 가운데 (VCC) | **물리 17 (3.3V)** | ⚠️ **5V 금지** — 내장 풀업 탓에 S의 HIGH=VCC 전압이 그대로 GPIO로 감 |
| `-` (GND) | 물리 9 (GND) | — |
| 바퀴 자석 | 4개 · 90° 간격 · **N-S-N-S 극성 교대** | 래치형이라 같은 극만으론 토글 불가 |

- `config.py`: `ENCODER_PIN = 22` 반영 완료(PC 188 GREEN · Pi 171 GREEN)
- `ENCODER_PULSES_PER_REV`: 자석 재배치 후 실측 확정(예상 2) — 현재 4 유지 중

## 6. 남은 작업

1. **자석 확보 → N-S 교대 배치** (자석 부족으로 세션 중단, 2026-08-24)
2. `calibrate_encoder.py --rev 5` → `ENCODER_PULSES_PER_REV`(예상 2)·바퀴 둘레 확정
3. 저속(0.1 m/s) 펄스 간격 실측 → 회전당 2펄스면 간격 ~1s → `STALL_TIMEOUT_S` 1.5→2.0s 상향 검토
4. 이후 R2 체인 계속: `setup_check.py --pwm --jitter` → B6a 실측 → `pid_tune.py --real`

## 7. 교훈

- **5V 풀업 내장 모듈 절대 금지**는 이론이 아니라 실제로 핀을 태운다 — 새 센서 연결 전 "HIGH가 몇 V로 나오는가"부터 확인
- 같은 증상이 모듈 교체 후에도 반복되면 **보드(Pi) 쪽을 의심** — `pinctrl get <pin>`으로 빈 핀+풀업 레벨을 보면 1분 만에 판정된다
- 홀센서는 "스위치형 vs 래치형"을 반드시 구분 — LED가 자석을 떼도 꺼지지 않으면 래치다

## 2. 새로 발견된 문제 (미해결 — 다음 세션)

### 2-1. 자석 프린지(옆면) 자기장 깜빡임 — 🔶 소프트웨어로 완화
- 관찰: 자석 정면에선 정상 감지, **약간 옆에서 접근할 때 LED가 반대로 깜빡** — 자석 측면의 반대 방향 프린지 자기장이 래치를 순간 토글.
- 5바퀴 11펄스(기대 10)의 초과 1펄스가 이것으로 추정.
- 조치: 10ms 디바운스로 카운트에서 필터링. ⬜ 모터 구동 속도에서 재검증. 근본 완화는 센서-자석 간격 축소.

### 2-2. ⚠️ **모터 한쪽 채널 무동작**
- 45%→70% 양채널 구동: **한쪽 바퀴만 회전**, 반대쪽 무동작.
- 채널 분리(ENA만 3s → ENB만 3s, 듀티 50%): **양쪽 다 무동작** — 직후 70% 재시도는 링크 단절로 미실행.
- 용의자: ① 죽은 채널 배선(ENA/ENB 선·IN 하드와이어·OUT→모터선) ② 배터리 전압 강하/커넥터(50%에서 양쪽 다 안 돈 것과 부합) ③ 시동 토크 부족(50% < 시동 임계)
- ⬜ 다음 세션: 양채널 70% 재시도 → 채널 분리 재시도 → 배선·배터리 추적. **자석 바퀴가 어느 채널인지 확인**(모터 구동 시 엔코더 0펄스와 연관).

### 2-3. ⚠️ **노트북 직결 이더넷 링크 플래핑** (세션 진행 불가 수준)
- 증상: SSH 1~2분 간격 끊김/복구 반복. Pi는 무관(재부팅 없음·throttled=0x0).
- 시도: ① IPv6 링크로컬 별칭 `kick-lan6` ② 킵얼라이브 핑 ③ USB 랜 어댑터 "Idle Power Saving" 비활성(관리자) — **③ 이후에도 재발** → 어댑터 절전 단독 원인 아님.
- 남은 용의자: 랜선/커넥터 접촉·USB 포트·Pi 이더넷.
- **결정: 다음 세션은 다른 와이파이 환경에서 SSH로 진행**(직결 포기). 핫스팟 시절(`kick-ip` 192.168.79.x)은 장시간 안정적이었음.
- 재사용할 우회 패턴: 측정·모터 스크립트를 **Pi에 nohup 분리 실행 + 로그 회수** → SSH 단절 무관. 모든 모터 스크립트는 자체 시간 제한 + `finally`/`atexit` 정지.
