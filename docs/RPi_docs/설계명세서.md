## 0. 변경 배경 & 설계 원칙

기존 **ESP32(수집부) + 라즈베리파이(구동·추론)** 분리 구조를, ESP 업로드 난항·통신 복잡도·도메인 갭 제거를 위해
**라즈베리파이 하나로 통합**한다. Pi가 4가지를 담당: **① RC카 구동 ② 속도제어 ③ 데이터 수집 ④ 앱 통신**.

**★ 설계 원칙 — 독립 개발 후 통합**
- 4가지는 **각각 독립 서브시스템**으로 개발한다(한 번에 만들지 않는다).
- 서로는 **계약(인터페이스)만** 알고, 내부 구현은 모른다 → 각자 따로 만들고·테스트하고, 마지막에 **통합 계층**이 조립.
- 통합 순서: 각 서브시스템 단독 완성 → 계약대로 연결.
- 기존 ESP 코드(`collector/`)는 `archive/collector-esp/`로 보존.

## 2. 공통 계약 (모든 서브시스템의 접점)

먼저 **이 계약들을 고정**해야 각자 독립 개발이 가능하다.

**자료형**
```python
Sample = { "t_ms": int, "ax","ay","az": int, "gx","gy","gz": int, "wheel_pulse": int }
RoadClass = "asphalt" | "bike_path" | "sidewalk_block" | "concrete" | "gravel"
Mode = "IDLE" | "COLLECT" | "DEMO"
```

**샘플 스트림**: `③ 데이터수집`이 `sample_queue`(Sample 스트림)를 생산 → 수집(로거)·인지가 소비.

**앱 명령/텔레메트리(④ 계약)** — ✅ **확정본은 [`공통계약.md`](공통계약.md) 계약 2** (앱 완성본 기준, issue #10 종결 2026-08-14)
- 명령(앱→Pi): `SET_MODE {COLLECT|DEMO}` · `START` · `STOP` · `LIST_FILES` · `RENAME` · `MEMO`
- 응답(Pi→앱): `type` 필드 — `ACK`/`ERROR`/`FILES`/`STATUS{speed,distance,vibration,roadType}`
- 라벨링 = 수집 후 `RENAME`으로 파일명 부여 (~~SET_LABEL~~ 폐기)

# 서브시스템 명세 (각각 독립 개발)

각 절: **목적 / 인터페이스(계약) / 입출력 / 의존 / 단독 테스트 / 담당**

## ① RC카 구동 (drive)  · `pi/motion/motor.py`

- **목적**: 모터에 PWM 듀티 출력. 직진/정지만(조향 없음).
- **인터페이스**
  ```python
  class Motor:
      def set_duty(self, duty: float): ...   # 0.0~1.0, 직진 속도
      def stop(self): ...                    # 즉시 정지(안전)
  ```
- **입력**: duty 명령 → **출력**: L298N ENA·ENB GPIO PWM (좌·우 같은 듀티, 방향 IN1~4은 하드웨어 고정)
- **의존**: GPIO(`gpiozero`+`lgpio`) — 다른 서브시스템 의존 없음
- **단독 테스트**: 듀티 주면 바퀴 회전, `stop()` 즉시 정지 (바퀴 공중)
- **담당**: 동제 (dj)

## ② 속도제어 (speed control)  · `pi/motion/speed_controller.py`

- **목적**: 목표 속도를 유지/도달. 엔코더 피드백으로 듀티 조정.
- **인터페이스**
  ```python
  class SpeedController:
      def set_target(self, speed): ...   # 목표 속도(또는 목표 듀티)
      def update(self): ...              # 주기 호출: 엔코더 읽어 Motor 듀티 보정
      def stop(self): ...
  ```
- **입력**: 목표속도 + 엔코더 속도 → **출력**: ①`Motor.set_duty()` 호출
- **의존**: **①(Motor)**, 엔코더(③의 센서 or 공유 엔코더 드라이버)
- **단독 테스트**: 목표속도 주면 바퀴가 그 속도로 수렴(엔코더 로그 확인)
- **담당**: 동제 (dj)
- ※ 1차는 오픈루프(고정 듀티 테이블)로 시작 → 필요 시 PID 피드백.

## ③ 데이터 수집 (data collection)  · `pi/sensors/` + `pi/collect/`

- **목적**: IMU+엔코더를 200Hz로 샘플링해 `sample_queue` 생산, 수집모드에선 CSV 저장.
- **인터페이스**
  ```python
  class Sampler:                 # sensors/sampler.py (스레드)
      def start(self): ...       # FIFO drain+엔코더 → sample_queue
      def stop(self): ...
  class Logger:                  # collect/logger.py
      def open(self, label: str): ...
      def write(self, s: Sample): ...
      def close(self): ...
  ```
- **입력**: 센서(MPU FIFO, 엔코더) → **출력**: `sample_queue` + `run_XXXX.csv`
- **의존**: MPU(`smbus2`), 엔코더(GPIO). 다른 서브시스템 의존 없음.
- **단독 테스트**: 정지 시 az≈1g, **실측 200Hz**, CSV 행수≈시간×200·gap 없음
- **담당**: 찬우 (cw)
- **CSV 스키마**: `timestamp_ms, ax, ay, az, gx, gy, gz, wheel_pulse`

## ④ 앱 통신 (app comm)  · `pi/comm/rfcomm_server.py` — ✅ 구현 완료 (B3, 2026-08-24)

- **목적**: RFCOMM(SPP) 소켓 서버. 앱 명령 수신·ACK/ERROR 응답 + STATUS 주기 송신 + 파일관리(LIST/RENAME/MEMO).
- **구성** (`pi/comm/`)
  - `protocol.py` — 순수 로직. `parse_command()`(앱 JSON → 정규화 dict, 불량이면 `ProtocolError(cmd,message)`) · `encode_ack/error/files/status()` · `ROAD_DISPLAY`(코드↔한글)
  - `files.py` — `FileManager(LOG_DIR)`: `list()`(csv만 정렬) · `rename()` · `memo()`(`<이름>.memo.txt` 사이드카, RENAME 시 동반 이동). 경로 탈출·비csv 거부 → `FileError`
  - `rfcomm_server.py` — `RfcommServer(listener, files)`: accept 스레드 1개, 줄단위 처리. 파일 명령은 자체 처리, 제어 명령은 콜백. `make_rfcomm_listener()`(표준 `socket.AF_BLUETOOTH`, 채널 1)
- **인터페이스** (공통계약 `BleServer` — 이름 유지, 구현은 RFCOMM)
  ```python
  class RfcommServer:
      def on_command(self, cb): ...      # cb(command_dict) -> bool. True=ACK / False=ERROR 응답
      def on_disconnect(self, cb): ...   # 끊김 → controller.on_disconnect(모터 정지, §6)
      def send_telemetry(self, data): ...# {speed, distance, vibration, road} → STATUS(roadType 한글)
      def start(self) / stop(self)       # 접속 대기 스레드 시작/종료
  ```
- **동작**: 파싱 실패·미지 명령 → `ERROR` 후 연결 유지. controller 예외 → `ERROR`, 서버 유지. 끊김 → 훅 호출 후 **다음 접속 대기**(재접속 가능). 클라이언트 없을 때 STATUS는 무시.
- **의존**: 파이썬 표준 `socket`(RFCOMM) + BlueZ. ~~bluezero~~ 제거. **Pi 준비**: `sudo bash scripts/rfcomm_setup.sh` — bluetoothd `-C` + `sdptool add SP`(앱이 UUID 00001101로 채널을 찾음) + discoverable
- **테스트**: 31 tests(`test_protocol/test_files/test_rfcomm_server`) — 서버는 **TCP 루프백으로 실제 소켓 경로** 검증. ⬜ 남음: Pi 실기 bind·앱 E2E(B9)
- **담당**: 찬우 (cw) — Pi측 서버 (스마트폰 앱 자체는 도현/`app`)

## (공유) 노면 인지 (perception/inference)  · `pi/infer/` + `pi/policy.py`

> ③의 샘플 스트림을 받아 ②의 목표속도를 만드는 **두뇌**. 4서브시스템을 잇는 핵심이라 별도 명시.

- **목적**: 샘플 → 윈도우 → 노면 분류 → 목표속도.
- **인터페이스**
  ```python
  class Windower: def add(self, s: Sample) -> Window | None: ...
  class Model:    def predict(self, w: Window) -> RoadClass: ...
  def policy(road: RoadClass) -> target_speed: ...
  ```
- **의존**: ③의 `Sample` 계약(스트림). 하드웨어 비의존.
- **단독 테스트**: 저장된 CSV로 **오프라인 예측**, mock 윈도우로 로직 검증
- **담당**: 찬우 (cw) — 학습은 PC(`scripts/train.py`, sklearn RF), 추론만 Pi(`ForestModel` — RF를 JSON으로 내보내 **numpy만으로** 추론, TFLite 불필요). 저신뢰(<0.5) → `unknown` → 감속. 거리 윈도우(`DistanceWindower`)는 C3 비교용.

# 통합 계층

## 3. 통합 계층 (controller)  · `pi/controller.py` + `pi/main.py`

위 5개를 **모드에 따라 연결**하는 얇은 오케스트레이터. 각 서브시스템의 **인터페이스만** 호출(내부 모름).

```
COLLECT:  ③Sampler → ③Logger(CSV)        ;  ②SpeedController=순항 → ①Motor
DEMO:     ③Sampler → 인지(Windower→Model→policy) → ②SpeedController → ①Motor
          Controller → ④BleServer.send_telemetry(노면·속도)
④ 명령(SET_MODE/START/STOP) → Controller 상태 전이
```

- Controller는 각 파트를 **주입(의존성 주입)** 받아 조립 → 파트 교체·mock 쉬움.
- 각 서브시스템이 **먼저 단독 완성**되어 있으면, 통합은 "계약대로 배선"만.

## 4. 동시성 모델

**단일 프로세스, 3 스레드 + 2 큐**
- **Sampler 스레드**(③): FIFO drain(HW 200Hz) → `sample_queue` (지터는 FIFO가 흡수)
- **Controller 스레드**: `sample_queue` 소비 → 모드별 라우팅, `②.update()` 주기 호출, telemetry 갱신
- **RFCOMM 스레드**(④): 명령 in / 텔레메트리 out
- 공유: `sample_queue`(③→Controller), `command_queue`(④→Controller), `telemetry`(Controller→④, lock)
- **motor는 ②/Controller 경로만** 조작(단일 writer). GIL은 C 백엔드(I2C·numpy·PWM)라 무해(Pi 5).

## 5. 모드 & 상태머신

`INIT → IDLE ↔ COLLECT / DEMO` (+ SAFE)

| 현재 | 트리거 | 동작 | 다음 |
| --- | --- | --- | --- |
| INIT | init 완료 | ④ 접속 대기 시작 | IDLE |
| IDLE | `SET_MODE` | 모드 선택 저장 | IDLE |
| IDLE | `START`(collect) | ③Logger.open, ②순항 | COLLECT |
| IDLE | `START`(demo) | ②순항 | DEMO |
| COLLECT | `STOP` | ③Logger.close, ①stop | IDLE |
| DEMO | `STOP` | ①stop | IDLE |
| COLLECT/DEMO | **앱 끊김/에러** | **즉시 ①stop**+(수집이면 파일보존) | IDLE(SAFE) |

**시작 시퀀스**(`main.py`): config → ③센서 init → ①모터 init(**정지 확정**) → 인지 모델 로드 → ③Sampler 스레드 → ④RFCOMM 대기 → **IDLE**.

## 6. 에러 처리 & 안전 (공통)

**대원칙: 불확실하면 느리게/정지. 모터 기본상태 = 정지.**

| 실패 | 감지 | 대응 |
| --- | --- | --- |
| IMU 초기화 실패 | WHO_AM_I | IDLE 유지·보고 |
| IMU 읽기 에러 | I2C 예외 | 재시도→SAFE(①stop) |
| FIFO 오버플로 | 플래그 | FIFO 리셋+gap 로그 |
| 엔코더 무펄스 | 일정시간 0 | 속도0 취급·경고 |
| 디스크 풀/쓰기실패 | 예외·사전체크 | 녹화중단·파일닫기·보고 |
| 모델 로드 실패 | 파일없음 | DEMO 비활성(COLLECT 가능) |
| 추론 예외/저신뢰 | 예외·confidence↓ | 윈도우 스킵→기본 감속 |
| 앱(RFCOMM) 끊김 | 소켓 EOF | **즉시 ①stop**+다음 접속 대기 |
| 제어 예외 | try/except | 듀티0·GPIO LOW·SAFE |

- **워치독(필수)**: Controller 주기 kick, Sampler 사망/정지 >500ms → 워치독이 ①stop.
- **데이터 무결성**: 버퍼링 write + 1초 fsync(손실 ≤1초), 1주행=1파일, 비정상 종료에도 flush·close.
- **자원 정리**: signal(SIGTERM/SIGINT)·atexit → ①stop→파일close→GPIO정리→④정지.

## 7. 데이터 & ML 규격

- **200Hz 근거**: 노면 고주파 정보(자갈길 등)를 담으려면 나이퀴스트상 대역폭×2. DLPF 94Hz로 안티에일리어싱.
- **윈도우**: 1차 시간(0.5~1초)+속도 feature → 2차 거리(1~2m 리샘플). 비교 실험 = 보고서 어필.
- **학습/추론 분리**: 학습 PC(sklearn RF, 세션단위 train/test 분리, 혼동행렬) → **RF를 JSON으로 내보내** Pi는 `numpy`만으로 추론(`pi/infer/forest.py`). ~~TFLite~~ 폐기(2026-08-24).
- **노면 5종 + 기타**: 아스팔트·자전거도로(안전) / 보도블럭·콘크리트(주의) / 자갈길(위험) / 기타→`unknown`(fail-safe 감속). 앱 표시명·매핑은 공통계약 계약 2.

## 8. 하드웨어 / 배선 (Pi 5) — 4WD · L298N 확정 (2026-07-27, DJ)

> 구동: **4WD, L298N 2채널**(좌=ENA→OUT1/2 / 우=ENB→OUT3/4). **직진 전용**.
> 속도센서: **KY-003 홀센서 모듈 + 자석 확정** (광엔코더 폐기 · A3144 베어 소자 계획은 래치형 모듈 실물 기준으로 재확정 2026-08-24).
> 핀 단일 출처: `RPi/pi/config.py`.
> ⚠️ **공통 자산 변경** — 드라이버·전원 반영은 전원 담당(찬우)에게 **통지·합의 후** main 머지.
> ✅ **전류·전원 재계산 완료** (2026-08-10, DJ) → [`전원계산.md`](전원계산.md). 요약: 모터 **TT 1:48**, 배터리 **2S 18650**(컷오프 7.0V), Pi는 **USB PD 보조배터리 별도**(벅컨버터 불필요).
> ⚠️ L298N은 **정상 주행은 여유 충분하나 스톨 시 채널 연속정격(2A) 초과** → `DUTY_MAX=0.75`·소프트스타트·스톨감지·방열판 **4개가 전제**. ✅ 코드 3종은 B6a 완료(`pi/safety.py` `SoftStartMotor`·`StallDetector`, `config` `SOFT_START_S`·`STALL_TIMEOUT_S`); 방열판은 하드웨어.

| 서브시스템 | 신호 | Pi 5 핀(BCM) | 인터페이스 |
| --- | --- | --- | --- |
| ③ MPU-6050 | VCC / SDA / SCL | 3.3V(물리1) / GPIO2 / GPIO3 | I2C-1 (AD0=GND → 0x68) |
| ③/② KY-003 홀센서 모듈 | VCC / 신호(S) | **3.3V(물리17)** / **GPIO22(물리15)** | GPIO 인터럽트 · 풀업 모듈 내장(외부 저항 불필요) · ⚠️ GPIO17(물리11)은 핀 손상으로 사용 금지 |
| ① L298N 좌(ENA) | 속도 PWM | GPIO18 | PWM (`lgpio.tx_pwm`) |
| ① L298N 우(ENB) | 속도 PWM | GPIO13 | PWM (`lgpio.tx_pwm`) |
| ① L298N IN1~IN4 | 방향(고정) | — | 보드에서 +5V/GND 고정(전진) |
| (임시) 지터 측정 | 루프백 입력 | GPIO27 | `setup_check.py --jitter` 때만 ENA에서 점퍼 |
| 공통 | GND | GND | 공통 접지 |

- **직진 전용**: IN1·IN3=+5V, IN2·IN4=GND로 **하드웨어 고정**(전진). Pi는 방향 GPIO를 안 쓰고 속도(ENA·ENB PWM)만 제어. 정지=ENA/ENB PWM 0.
- ⚠️ L298N **ENA·ENB 점퍼캡 제거**해야 PWM 동작(안 빼면 최고속 고정). **`5V EN` 점퍼는 반대로 꽂아둔다**(VMS 8.4V ≤ 12V → 온보드 레귤레이터가 로직·IN1~4 고정용 +5V를 공급).
- ⚠️ **KY-003 모듈은 풀업이 VCC로 내장**되어 S의 HIGH가 VCC 전압 그대로 나온다 → **반드시 3.3V 급전(5V 금지)**. 3.3V에서 감지 동작 실측 확인(2026-08-24). 5V 풀업 내장 보드가 GPIO17을 손상시킨 이력 있음 — [홀센서_트러블슈팅.md](홀센서_트러블슈팅.md)
  **베어 소자 + 별도 10kΩ**을 쓸 것 — 풀업이 내장된 3핀 모듈을 5V로 급전하면 DO가 5V로 나와 **GPIO가 손상**된다.
- 자석은 **구동륜 1개**에만 90°마다 4개. PPR=자석 수 → `ENCODER_PULSES_PER_REV` 실측 보정.
- ⚠️ **Pi 5V 핀(물리 2번) 급전 금지** — Pi는 USB-C PD 보조배터리로 급전한다([`전원계산.md`](전원계산.md) §5). 5V 핀 급전은 PMIC 보호를 우회한다. 물리 4번(5V 출력)은 현재 미사용(홀센서는 3.3V 물리17로 이전).
- ⚠️ L298N 보드의 **`5V` 단자는 출력**이다. Pi 5V와 절대 연결하지 않는다.
- L298N 전압강하 ~2V(모터가 배터리보다 약하게 돔)·발열 → **방열판 필수**. Pi 전원은 L298N 5V(0.5A) 금지.
- ⚠️ **모터·Pi 전원 격리** → **Pi는 USB PD 보조배터리(5V/3A↑)로 완전 분리** 확정([`전원계산.md`](전원계산.md) §5). 모터 레일엔 1000µF 벌크.
- ⚠️ **전원 격리 ≠ 접지 분리** — 전원 레일은 나누되 **GND는 반드시 공통**. 안 묶으면 PWM·홀센서 신호가 기준을 잃어 아무것도 동작하지 않는다.

## 9. 개발 순서 (독립 → 통합)

1. **① 구동** 단독 (바퀴 공중, 듀티·정지 확인)
2. **③ 데이터 수집** 단독 (200Hz·CSV·gap 없음)
3. **④ 앱 통신** 단독 (폰↔더미 명령·텔레메트리)
4. **② 속도제어** (①+엔코더 결합, 목표속도 수렴)
5. **인지** (③의 CSV로 오프라인 학습·예측)
6. **통합 계층** (계약대로 배선 → 모드 동작)

각 단계는 서로 **병렬 진행 가능**(계약 고정 덕분).
