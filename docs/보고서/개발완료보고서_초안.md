### `[2]` 작품 한 장 요약 🟩
- **한 문장**: 노면 진동을 IMU로 읽어 노면 재질을 분류하고, 위험하면 스스로 감속하는 킥보드.
- 동작 흐름 그림: 노면 → 진동(MPU-6050 200Hz) → 윈도우·특징 → RandomForest 분류 → 속도 정책(안전 0.4 / 주의 0.25 / 위험 0.1 m/s) → PID 속도제어 → 앱에 노면·속도 실시간 표시.
- 노면 6분류: 아스팔트·자전거도로(안전) / 보도블럭·콘크리트(주의) / 비포장(위험) / 기타(**fail-safe 감속**).

### `[3]` 개발 범위·성공 기준 🟩/🟨
- RC카(킥보드 모형, 4WD 직진·정지)로 **데이터 수집과 시연을 동일 차체**에서 수행 → 학습=배포 환경 일치(도메인 갭 0)가 설계의 축.
- 성공 기준 표: 분류 정확도(세션 분리) 🟨 / DEMO 감속 반응 <1초 / COLLECT 샘플 결손 0 / 안전 시나리오(끊김·워치독·SIGTERM·스톨·저신뢰) 전부 정지·감속.

## 2. 개발 환경 설명 — `[4~6]` (§2+§3+§4 합계 10P)

### `[4]` HW 구성 및 기능 🟩
- 구성도(사진+배선도 캡처: 📎 `docs/RPi_docs/핀맵.html`, `L298N배선.html`):
  **Raspberry Pi 5**(모든 SW 통합) · L298N 모터드라이버(방향 하드와이어 고정, ENA/ENB PWM만 제어) · TT 기어드모터 ×4 · MPU-6050 IMU(I2C, HW FIFO) · A3144 홀센서+자석 4개(엔코더) · 2S 18650(모터 전원, 컷오프 7.0V) + USB PD 보조배터리(Pi 전원, **전원 분리·GND 공통**) · 1000µF 콘덴서·방열판 · **아크릴 RC카 섀시**(기성 모형 — IMU 리지드 마운트).
- 부품 선정 근거 한 줄씩: L298N 열 여유 계산(스톨 2.4A > 정격 2A → §4 안전 3종의 근거), 홀센서 4펄스/회전 저속 대응(주기 기반 속도).

### `[5]` SW 구성·기능 설계도 🟩
- **1보드 통합 아키텍처**: Pi 5가 ①구동 ②속도제어 ③데이터수집 ④앱통신 + 노면인지 + 통합을 전담.
- **계약 기반 병렬 개발**: 서브시스템은 `Protocol` 인터페이스(Motor·SpeedController·Sampler·Logger·Windower·Model·BleServer)만 공유 → 팀원별 독립 개발 후 `controller`가 모드(IDLE/COLLECT/DEMO)별 배선. 📎 설계명세서 §3 구조도.
- 런타임: 3 스레드 + 2 큐 — Sampler(200Hz FIFO drain) → `sample_queue` → Controller(50Hz 제어 tick·5Hz STATUS) / RFCOMM 스레드. 워치독은 **별도 스레드**.
- Android 앱(RFCOMM 컨트롤러): 모드 토글·출발/정지·노면/속도 표시·파일 관리(라벨링).

### `[6]` 개발 환경 🟩
- Pi: Raspberry Pi OS(Debian 13)·Python 3 — `smbus2`(I2C)·`gpiozero`+`lgpio`(PWM)·`numpy`·표준 `socket`(RFCOMM). **추론에 sklearn/TF 불필요.**
- PC(학습·개발): Windows + pytest **188 tests**(PC·Pi 동일 실행)·sklearn(학습 전용). 앱: Android Studio·Kotlin.
- 협업: GitHub 브랜치(cw/dj/dh/mj)+PR 규칙, 계약 문서(공통계약.md)가 단일 출처.
- ※ 규정 제10조 대응 — 오픈소스 사용 명시: Python 표준 라이브러리·numpy·scikit-learn(BSD)·gpiozero/lgpio(MIT/LGPL)·smbus2(MIT). 애플리케이션 코드는 전량 자체 작성.

### `[8]` 흐름도 🟩 — 모드 상태머신 + 데이터 경로
- 상태머신: IDLE ↔ COLLECT / DEMO, 모든 이상 경로(STOP·앱 끊김·에러·워치독·스톨·SIGTERM)가 `_safe_stop`(**모터 먼저 정지**→파일→IDLE) 한 곳으로 수렴하는 다이어그램.
- COLLECT: 샘플→CSV(결손 0, FIFO) / DEMO: 샘플→윈도우→특징→RF→정책→PID.

### `[9]` 노면 인지 파이프라인 🟩/🟨 (기술적 차별성 ①)
- 200Hz 샘플링 근거(나이퀴스트: 노면 단서 ~100Hz, DLPF 94Hz), **MPU HW FIFO**로 리눅스 스케줄링 지터 흡수 — 타임스탬프는 FIFO 인덱스×5ms 재구성.
- 특징 8종(az DC 제거): RMS·분산·PTP·ZCR·지배주파수·대역에너지 3구간.
- **시간(0.5s) vs 거리(엔코더 펄스) 윈도우 비교 실험** — 속도가 변해도 "노면 길이"가 고정되는 거리 윈도우의 강건성 검증. 🟨 결과 수치.
- **RF→JSON→numpy 추론**: PC(sklearn)에서 학습한 RandomForest를 트리 배열 JSON으로 내보내 Pi에서는 numpy만으로 추론(<1ms, 의존성 0). sklearn 예측과 **비트 단위 일치**를 테스트로 보증. 세션(파일) 단위 GroupKFold로 시간 상관 누수 차단. 최다 확률 <0.5 → `unknown` → fail-safe 감속.
- 🟨 혼동행렬·정확도 캡처(`scripts/train.py` 출력).

### `[10]` 속도제어·앱 통신 🟩/🟨
- 속도: 홀센서 **주기 기반** 속도 추정(저PPR 저속에서도 안정) → PID(anti-windup) → PWM. 🟨 스텝 응답 그래프(`pid_tune.py --csv`): 상승시간·오버슈트·정상오차.
- 앱 통신: Bluetooth RFCOMM(SPP) 서버, 줄단위 JSON — 명령 `SET_MODE/START/STOP/LIST_FILES/RENAME/MEMO`, 응답 `ACK/ERROR/FILES/STATUS{speed,distance,vibration,roadType}`. 수집 후 RENAME으로 라벨링(현장 워크플로). 🟨 앱 화면 캡처.

### `[11]` 안전 설계 🟩 (기술적 차별성 ② — 움직이는 임베디드의 필수 조건)
- 5중 방어: ① 모든 종료 경로 `_safe_stop` 수렴 ② SIGTERM/atexit 핸들러 ③ **별도 스레드 워치독**(500ms 무응답→정지) ④ **스톨 감지**(1.5s 무펄스→정지) ⑤ 저신뢰 추론→감속.
- L298N 열 보호: `DUTY_MAX=0.75`·**소프트스타트**(0.4s 램프)·방열판 — 스톨 전류 계산 기반. 비상정지 `estop.py`.
- 검증: TDD 188 tests, 하드웨어 목(MockGpio/MockPlant) 폐루프 시뮬, RFCOMM은 TCP 루프백으로 실제 소켓 경로 검증, Pi 실기 동일 테스트.

## 5. 개발 결과물의 차별성 — `[14~16]` (§5+§6 합계 5P)

### `[14]` 인지 방식의 차별성 🟩
- 비교표: **진동(본작) vs 카메라 vs GPS 지도 기반** — 야간/역광/우천/터널/프라이버시/전력/원가 축으로 진동만 전 항목 유효.
- "노면이 어떻게 보이는가"가 아니라 **"실제로 어떤가"를 측정** — 낙엽 덮인 자갈길, 젖어서 검게 보이는 보도블럭에서도 동작.

### `[15]` 엔지니어링 차별성 🟩/🟨
- **학습=배포 동일 차체**(도메인 갭 0) — 모형이라서 생기는 제약을 설계 강점으로 전환.
- **거리 윈도우**: 속도와 무관하게 노면 길이 고정 → 속도 변화에 강건(비교 수치 🟨).
- **RF→numpy 탑재**: 추론 의존성 0·<1ms — 저가 MCU로도 이식 가능한 경량 설계.
- 안전 5중 방어 + TDD 188 tests + 계약 기반 4인 병렬 개발 — 완성도·팀 프로세스.

### `[16]` 정량 결과 요약 🟨
- 분류 정확도(세션 분리)·혼동행렬 / 감속 반응 시간 / 200Hz 유지율·FIFO 오버플로 0 / 안전 시나리오 통과표 — 시연 영상 타임스탬프와 연결.

## 6. 개발 결과물의 파급력 및 기대효과 — `[17]`

### `[17]` 🟩
- **시장성**: 공유 킥보드는 이미 IMU 내장 → 본 알고리즘은 **펌웨어 업데이트만으로** 전 차량 적용 가능(추가 BOM 0원). 운영사 관점: 사고율·보험비용 절감.
- **활용성**: 노면 위험 감속(B2C 안전) + 주행 로그의 노면 상태 지도화(B2G — 보도블럭 파손·포장 불량 자동 리포트).
- **발전 가능성**: 자전거·전동휠체어·배달로봇 등 경량 모빌리티 공통 적용, 거리 윈도우+경량 추론은 MCU급 이식 가능, 연합 데이터로 도시 노면 데이터셋 구축.
- **사회적 효과**: 킥보드 규제(속도 일괄 제한) 논쟁에 "노면 적응형 제한"이라는 기술적 대안 제시.
