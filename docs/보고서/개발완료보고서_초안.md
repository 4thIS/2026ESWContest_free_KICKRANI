# 개발완료보고서 초안 — 노면 감지 킥보드 (팀 **킥라니**)

> 제24회 임베디드SW경진대회 자유공모 · 예선 마감 2026-09-03 · PPT 20p 규격(필수 7항목)의 **원고**.
> 🟩 = 확정 내용 채움 · 🟨 = 실측/데이터 후 채움 · ⬜ = 미작성. 각 절 끝의 `[슬라이드 n]`는 배정 페이지.

## 1. 작품 개요 (3p)

### 1.1 배경·문제 🟩 `[1]`
- 공유 킥보드 사고의 상당수가 **노면 상태**(보도블럭 단차·자갈·젖은 콘크리트)에서 발생. 운전자는 노면을 늦게 인지하고 속도는 고정.
- 카메라 기반 노면 인식은 **야간·역광·비·프라이버시·전력**에 취약.

### 1.2 제안: 진동으로 "느끼는" 적응형 속도제어 🟩 `[2]`
- IMU 진동으로 주행 중 **노면 재질을 실시간 판별** → 위험 노면이면 **자동 감속**, 안전 노면이면 정상 속도.
- 핵심 논리: 카메라는 노면이 *어떻게 보이는지*를 보고, 진동은 *실제로 어떤지*를 느낀다 → 저전력·전천후·프라이버시.
- 노면 5종 + 기타: 아스팔트·자전거도로(안전) / 보도블럭·콘크리트(주의) / 비포장·자갈(위험) / 기타(fail-safe 감속).

### 1.3 목표·범위 🟩 `[3]`
- RC카(킥보드 모형, 4WD 직진/정지)로 **수집과 시연을 동일 차체**에서 수행 → 학습=배포 환경(도메인 갭 0).
- 성공 기준: 세션 단위 분류 정확도 🟨 __%, DEMO 반응 < 1초, 안전 시나리오 5종 전부 정지/감속.

## 2. 개발 환경 및 프로그램 설명 (10p)

### 2.1 시스템 구성 🟩 `[4]`
- **Raspberry Pi 5 + Python 3** 단일 보드가 ①구동 ②속도제어 ③데이터수집 ④앱통신 + 노면인지 + 통합을 모두 담당.
- 하드웨어: L298N(4WD, 방향 하드웨어 고정, PWM ENA/ENB) · TT 모터 ×4 · MPU-6050(I2C, 200Hz FIFO) · A3144 홀센서(4펄스/회전) · 2S 18650 + Pi 별도 USB PD · GND 공통.
- 앱: Android, Bluetooth RFCOMM(SPP) 줄단위 JSON.
- 그림: 📎 `docs/RPi_docs/핀맵.html`, `L298N배선.html` (배선도 캡처)

### 2.2 소프트웨어 아키텍처 🟩 `[5]`
- **계약 기반 독립 개발**: 4 서브시스템이 `Protocol` 인터페이스(`Motor`·`SpeedController`·`Sampler`·`Logger`·`Windower`·`Model`·`BleServer`)만 공유, `controller`가 모드(IDLE/COLLECT/DEMO)별로 배선.
- 3 스레드 + 2 큐: Sampler(200Hz drain) → `sample_queue` → Controller(50Hz 제어, 5Hz STATUS) / RFCOMM 스레드.
- 그림: 📎 설계명세서 §3 구조도

### 2.3 데이터 수집 (③) 🟩 `[6]`
- 200Hz 근거: 노면 고주파 단서(~100Hz)를 담기 위한 나이퀴스트, DLPF 94Hz. MPU **하드웨어 FIFO**로 리눅스 지터 흡수, 타임스탬프는 인덱스×5ms 재구성.
- 1주행 = 1 CSV(`timestamp_ms,ax,ay,az,gx,gy,gz,wheel_pulse`, raw LSB), 1초 fsync. 라벨은 앱에서 수집 후 RENAME(`<원본>_<노면>_<상태>.csv`).

### 2.4 노면 인지 (윈도우·특징·모델) 🟩/🟨 `[7-8]`
- 윈도우: 시간 0.5s(100샘플, 50% 오버랩) vs **거리 윈도우**(엔코더 펄스 기준, 속도 무관 노면 길이 고정) 비교 실험.
- 특징 8종(az DC 제거): RMS·분산·PTP·ZCR·지배주파수·대역에너지(0-20/20-50/50-100Hz).
- 모델: RandomForest(PC 학습, 세션 단위 GroupKFold) → **JSON 내보내기 → Pi에서 numpy만으로 추론**(의존성 0, <1ms). 최다 확률 < 0.5 → `unknown` → 감속.
- 결과: 🟨 혼동행렬·정확도(시간 vs 거리 윈도우) — `scripts/train.py` 출력 캡처.

### 2.5 속도제어 (②) 🟩/🟨 `[9]`
- 엔코더 주기 기반 속도 → PID → PWM. 정책: 안전 0.4 / 주의 0.25 / 위험 0.1 m/s (🟨 실측 후 확정).
- 🟨 스텝 응답 그래프(`scripts/pid_tune.py --csv`): 상승시간·오버슈트·정상오차.

### 2.6 앱 통신 (④) 🟩 `[10]`
- RFCOMM(SPP) 서버, 명령 `SET_MODE/START/STOP/LIST_FILES/RENAME/MEMO`, 응답 `ACK/ERROR/FILES/STATUS{speed,distance,vibration,roadType}`. 앱 화면 캡처 🟨.

### 2.7 안전 설계 🟩 `[11]`
- 모든 정지 경로가 `_safe_stop`(모터→파일→IDLE)으로 수렴: STOP·앱 끊김·에러·SIGTERM/atexit·**워치독**(500ms)·**스톨 감지**(1.5s 무펄스)·저신뢰 감속.
- L298N 열 여유: `DUTY_MAX=0.75`·**소프트스타트**(0.4s 램프)·방열판. 비상정지 `scripts/estop.py`.
- 실기 사고 사례: `timeout` 강제종료 시 `finally` 미실행 → GPIO HIGH 잔존 → **시그널 핸들러로 해결**(보고서 "장애 극복"에 재사용).

### 2.8 개발·검증 방법 🟩 `[12-13]`
- TDD(RED→GREEN), pytest **188 tests**(PC·Pi 동일), 하드웨어 목(MockGpio/MockPlant)으로 폐루프 시뮬레이션, RFCOMM은 TCP 루프백으로 실제 소켓 경로 검증.
- 실기 검증 체크리스트: `setup_check.py`, 홀센서 보정(`calibrate_encoder.py`), 200Hz/FIFO/CSV gap.

### 3.2 차별성 🟩 `[16]`
- 카메라 없이 **진동만으로** 노면 판별 → 전천후·저전력·프라이버시.
- **거리 윈도우**로 속도 변화에 강건한 특징(비교 실험 수치 🟨).
- 수집=시연 동일 차체, 계약 기반 병렬 개발, 안전 경로 단일화.

### 3.3 기대효과 🟩 `[17]`
- 공유 킥보드에 **센서 추가 없이**(기존 IMU) 소프트웨어로 노면 적응 감속 → 사고 예방.
- 노면 상태 로그 → 도로 관리 데이터(보도블럭 파손 지도) 부가 가치.
